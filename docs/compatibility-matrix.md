# Cross-Agent Compatibility Matrix

Last reviewed: 2026-07-04

This matrix records only official documentation claims from `docs/official-sources.json`. If a feature is absent from official docs, write `not documented` instead of inferring support.

Two rows are **non-vendor** and flagged as such: **Kuma Studio** (private runtime policy) and **gajae-code** (`gjc`, a community/MIT beta by Yeachan-Heo — its GitHub README is the only source, not vendor docs; claims below verified against the README on 2026-06-27). Do not read these two rows as official vendor guarantees.

## Skill Invocation

How a *typed* command reaches a skill differs per runtime — the explicit-invocation token is **not** portable, even where the `SKILL.md` format is. Do not assume `/<skill-name>` works everywhere.

| Platform | Explicit (user-typed) invocation | Model-triggered invocation | Source (verified 2026-06-22) |
|---|---|---|---|
| Claude Code | `/<skill-name>` — "You can type `/skill-name` to invoke it directly." Custom commands are merged into skills (`.claude/commands/deploy.md` and `.claude/skills/deploy/SKILL.md` both create `/deploy`). | Claude loads a skill automatically when relevant. `disable-model-invocation: true` restricts a skill to user-only invocation (removes it from Claude's context and from subagent preloading). | https://code.claude.com/docs/en/skills (verified 2026-06-22) |
| OpenAI Codex | `/skills` opens the skill selector; `$<skill-name>` mentions a skill in the prompt ("run `/skills` or type `$` to mention a skill"). Typing `/<skill-name>` is **not** a documented invocation form. | "Codex can choose a skill when your task matches the skill `description`." Disable with `allow_implicit_invocation: false` in the skill's `agents/openai.yaml`. | https://developers.openai.com/codex/skills |
| Grok / xAI | "User-invocable skills also appear as slash commands, for example `/<skill-name>`." | Automatic invocation mechanics are not detailed in the cited page; discovery and slash invocation are. | https://docs.x.ai/build/features/skills-plugins-marketplaces |
| Hermes Agent | not documented in the cited source set | Skills and skill preloading are documented; trigger mechanics not detailed. | https://hermes-agent.nousresearch.com/docs |
| Antigravity CLI | A registered skill auto-converts to a typed `/<skill-name>` slash command in the TUI ("the skill is compiled, and `/format-tests` becomes available"). | Skills are compiled from `.agents/skills/` (workspace) and `~/.gemini/antigravity-cli/skills/` (global) on launch; per-skill model-trigger toggles are not documented. | https://antigravity.google/docs/cli/plugins |
| Cursor CLI | Type `/` in Agent chat and search for the skill name. | Cursor automatically discovers skills from skill directories and the agent applies relevant ones. `disable-model-invocation: true` makes a skill explicit-only. | https://cursor.com/docs/skills |
| gajae-code (`gjc`, community) | `/skill:<name>` (colon form, e.g. `/skill:deep-interview`) — **not** `/<skill-name>`. List/read out of session with `gjc skills list` / `gjc skills read <name>`. | Not documented in the README; default skills are bundled but per-skill model-trigger toggles are not described. | https://github.com/Yeachan-Heo/gajae-code (README, verified 2026-06-27) |

Implementer note: a cross-engine "typed command" surface therefore cannot standardize on one token. Ship the capability as a skill with strong trigger terms in `description` (works everywhere via model-triggering), and treat `/name` (Claude/Grok) vs `$name` (Codex) as per-engine sugar. Do not re-implement a slash parser in a host GUI/terminal layer above the engines to paper over this — see SKILL.md → Core Rules.

## Session Resume

Same-platform resume (continue an existing conversation on the same engine, by session id) is officially documented for all four primary worker runtimes. Cross-engine moves are a separate concern and out of scope here.

| Platform | Resume invocation | Session store | Session id form | Source (verified 2026-07-04) |
|---|---|---|---|---|
| OpenAI Codex (CLI) | `codex resume <SESSION_ID>` or `codex resume --last` (interactive); `codex exec resume [SESSION_ID]` / `--last` (non-interactive). `--all` ignores the cwd filter. | On-disk paths are **no longer documented** (as of 2026-07-04 the CLI reference no longer states `~/.codex/sessions/` or `~/.codex/history.jsonl`). Rollout files still exist per `--ephemeral` ("run without persisting session rollout files to disk"); verify live paths before depending on them. | session id copied from the picker or `/status`. | https://developers.openai.com/codex/cli/reference |
| OpenAI Codex (app-server) | Call the `thread/resume` method with the recorded `thread.id` over the stdio app-server API. | Claude Code | `claude --resume <session-id>` (or `--continue` / `-c`, or `/resume`). Reopens under the same session id and appends. `--fork-session` copies into a new id. `claude --from-pr <number>` resumes the session linked to a pull request and also accepts GitHub Enterprise, GitLab MR, and Bitbucket PR URLs. | Grok / xAI | `grok -c, --continue` continues the most recent session in cwd; `grok -r, --resume <ID>` resumes by session id; `grok -s, --session-id <ID>` creates or resumes a named headless session. | Headless sessions are stored in `~/.grok/sessions` (per the official headless-scripting doc). The doc does **not** document an `active_sessions.json` live-session index or its field schema — treat that as `not documented`. | `session_id`. | https://docs.x.ai/build/cli/headless-scripting |
| Hermes Agent | `hermes --resume <session_id>` / `-r <session_id>`; `hermes --continue` / `-c` resumes the most recent; resume by title also supported. NOT the API error dumps under `~/.hermes/sessions/` (`request_dump_*.json`), which are unrelated. | `YYYYMMDD_HHMMSS_<suffix>` (e.g. `20260225_143052_a1b2c3`). | https://hermes-agent.nousresearch.com/docs/user-guide/cli/ |
| Antigravity CLI (`agy`, the Gemini CLI successor) | `agy --conversation <uuid>` pins a specific conversation; `agy --continue` resumes the most recent in the workspace; in-TUI `/resume` (`/switch`, `/conversation`) opens a picker, `/fork` (`/branch`) branches, and Tab imports Antigravity 2.0 desktop threads. Notes for implementers:

- The resume **locator** (session/thread id) plus the engine's resume invocation is the minimum needed to continue same-platform. Capture the locator before the worker exits, keyed by cwd (the most stable cross-engine signal exposed here).
- Codex workers launched through the desktop **app-server** (`codex app-server --listen stdio://`) resume via `thread/resume`, not a CLI flag. The rollout JSONL directory is no longer stated in either Codex doc (the CLI reference dropped `~/.codex/sessions/` / `~/.codex/history.jsonl` as of 2026-07-04) — verify the live rollout path before relying on a file-level integration.
- Hermes resume reads from `state.db` (SQLite), so a file-scan over `~/.hermes/sessions/` will not find resumable state — query the db (or the displayed "Resume this session with: hermes --resume <id>" line) instead.
- When a runtime does not document a resume capability, record `not documented` and require live verification before shipping.

## Project Instruction File Loading

The project-instruction *filenames* per engine are in the master table above; this section is the **loading mechanics** — how each engine discovers, merges, and times those files. Two axes matter and the engines diverge on both: (a) **ancestor walk-up** — does it climb from cwd toward the repo/filesystem root and merge every file it passes, or read only one? (b) **subdirectory (below-cwd) discovery** — does it pick up nested instruction files in child directories at all, and if so **upfront at launch** (always in context) or **on-demand** (only when the agent touches a file there)?

| Engine | Ancestor walk-up (cwd → root) | Multiple files merged? | Subdirectory (below cwd) | Subdir load timing | Build timing / caps | Source (verified 2026-06-22) |
|---|---|---|---|---|---|---|
| Claude Code | **Yes** — climbs cwd → filesystem root, loads every `CLAUDE.md` + `CLAUDE.local.md` in full at launch | **Yes** — concatenated root → cwd; closer-to-cwd read **last** (higher priority); `CLAUDE.local.md` appended after `CLAUDE.md` per level | **Yes** | **On-demand** — included when Claude reads a file in that subdir; **not** re-injected after `/compact` until that dir is touched again | Launch (ancestors) + lazy (subdirs). Root re-read on `/compact`. `--add-dir` dirs need `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`; `claudeMdExcludes` globs skip files. `@path` imports load in full at launch (depth ≤ 4) | https://code.claude.com/docs/en/memory |
| OpenAI Codex | **Yes** but **downward** — walks project root **down to** cwd; ≤ 1 file per directory | **Yes** — concatenated root → down; closer files **override** (appear later) | **No** — stops at cwd, does **not** scan deeper | n/a (no subdir lookahead) | Built **once per run**; global `~/.codex/AGENTS.override.md`/`AGENTS.md` first; `AGENTS.override.md` > `AGENTS.md` per dir; stops at `project_doc_max_bytes` (32 KiB default) | https://developers.openai.com/codex/guides/agents-md |
| Gemini CLI / Antigravity (`agy`) | **Yes** — `GEMINI.md` from cwd up to `.git` project root | **Yes** — global + ancestor + subdir all **concatenated** (separator format not documented) | **Yes** | **Always in context** — subdirs *below* cwd are concatenated and **sent with every prompt** (respects `.gitignore`/`.geminiignore`); the doc states the every-prompt concatenation but does **not** label the scan lazy-vs-eager | Global `~/.gemini/GEMINI.md` + ancestors + subtree; inspect with `/memory show`, refresh with `/memory refresh`. Antigravity inherits `GEMINI.md`+`AGENTS.md`; its exact per-file timing is the legacy Gemini-CLI form, not separately re-documented | https://google-gemini.github.io/gemini-cli/docs/cli/gemini-md.html |
| Hermes Agent | **No** (at launch) — loads **one** project file, first match wins: `.hermes.md` → `AGENTS.md` → `CLAUDE.md` → `.cursorrules` | **No** — single file; does not merge same-level or ancestor files at startup | **Yes** — progressive | **On-demand** — on file ops, the dir + up to **5 parent dirs** are checked (stopping at already-visited dirs) | `SOUL.md` (global identity from `HERMES_HOME`) always loads separately, regardless of cwd. Keeps system prompt stable + cache-friendly | https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files |
| Cursor CLI | **Not documented** — docs state only that **project-root** `AGENTS.md` + `CLAUDE.md` are read and applied as rules alongside `.cursor/rules` | Not documented | Not documented | — | Scoping is via `.cursor/rules` `.mdc` files with path globs (analogous to Claude `.claude/rules/`), not ancestor walk of `AGENTS.md` | https://cursor.com/docs/cli/using |
| Grok / xAI | Not separately documented — claims Claude Code compatibility + `AGENTS.md` family (`AGENTS.md`, `Agents.md`, `AGENT.md`) | Unknown (assume Claude-like only after live verification) | Unknown | — | Treat the tree/merge semantics as `unknown`; verify against the live engine before depending on ancestor or subdir behavior | https://docs.x.ai/build/features/skills-plugins-marketplaces |
| gajae-code (`gjc`, community) | **Not documented** — README describes no project-instruction-file loader at all | Not documented | Not documented | — | No `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` reader is described; config is `~/.gjc/config.yml` + per-project `.gjc/` state. Verify live before assuming any instruction-file support | https://github.com/Yeachan-Heo/gajae-code (README, verified 2026-06-27) |

Key contrasts for implementers:

- **Subdir support is not the same as subdir timing.** Claude Code and Hermes load nested files **on-demand** (only when the agent touches that directory), while Gemini/Antigravity concatenates the whole subtree and **sends it with every prompt** (always in context — the doc doesn't label the scan lazy vs eager, but it is never on-demand like Claude). Same feature, opposite cost profile: Gemini pays tokens for the entire tree every prompt; Claude/Hermes pay only for directories in play.
- **Codex has no subdir lookahead at all.** It stops at cwd and walks *root → down*, so a `AGENTS.md` deeper than your cwd is never seen. Put module-specific guidance at or above cwd, and remember the 32 KiB combined cap silently truncates a long chain.
- **Hermes is single-file, first-match — it does not merge.** A repo with both `AGENTS.md` and `CLAUDE.md` feeds Hermes only `AGENTS.md` (it wins the precedence) unless `.hermes.md`/`HERMES.md` exists. Cross-engine repos relying on a `CLAUDE.md`-imports-`AGENTS.md` split must keep the canonical content in the file Hermes actually picks.
- **"Closer wins" direction is consistent but the walk direction is not.** Claude climbs cwd → root; Codex descends root → cwd; both end with the file nearest cwd taking priority (read last). The user-visible rule ("the instruction nearest where you launched wins") holds across both, but the set of files reached differs because Codex never goes below cwd and Claude lazy-loads what's below.
- For undocumented engines (Cursor tree-walk, Grok merge semantics) record `not documented`/`unknown` and require live verification before shipping behavior that depends on ancestor or nested discovery.

## Update Rule

When official docs change:

1. Update `docs/official-sources.json` first if a source URL or claim category changes.
2. Update this matrix only with source-backed wording.
3. Keep differences explicit. Do not map `plugin`, `extension`, `skill`, and `command` to one shared term unless the vendor docs do so.
4. Leave a PR so the diff is reviewable before merge.
